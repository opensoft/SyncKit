# SyncKit Architecture Documentation

## Overview

SyncKit is a WSL-to-OneDrive synchronization system designed to automatically sync project files from Windows Subsystem for Linux (WSL) to OneDrive for backup and cross-platform access. The system provides intelligent, optimized bidirectional synchronization with git repository detection, conflict resolution, and comprehensive logging.

**Key Innovation**: Automatic git repository exclusion prevents branch conflicts across workstations while maintaining efficient sync of non-git project files.

## Implementation Details

### 1. SyncKit Script Suite

#### Core Scripts:
1. **`oneDriveDataSync.sh`** - Main bidirectional sync with optimizations
2. **`wsl-sync-to-onedrive`** - Manual WSL → OneDrive sync
3. **`wsl-sync-from-onedrive`** - Manual OneDrive → WSL sync
4. **`dataSync-installer.sh`** - Interactive configuration and installation

**Installed Location**: `~/.local/bin/wsl-bidirectional-sync` (for backwards compatibility)
**Source Location**: `projects/SyncKit/dataSync/scripts/`
**Language**: Optimized Bash with performance enhancements

#### Revolutionary Features:
- **🔍 Git Repository Detection**: Automatically excludes entire git repositories to prevent branch conflicts
- **⚡ Optimized Performance**: Fast file scanning, batch operations, smart caching
- **🔄 True Bidirectional Sync**: WSL ↔ OneDrive with conflict detection
- **🛠️ Interactive Configuration**: Auto-detects WSL and OneDrive paths
- **📊 Performance Metrics**: Detailed timing and transfer statistics
- **⚔️ Conflict Resolution**: Multiple strategies with detailed logging

### 2. Interactive Configuration System

#### Smart Path Detection:
**WSL Projects Directory Detection:**
- Scans common paths: `~/projects`, `~/dev`, `~/code`, `~/workspace`, `~/src`, `~/development`
- Prioritizes directories with git repositories
- Falls back to project count if no git repos found
- Allows manual override

**OneDrive Path Detection:**
- Auto-detects: `/mnt/c/Users/$USER/OneDrive*` (including business accounts)
- Suggests: `{detected_path}/projects/wsl`
- Validates accessibility and offers to create directories

#### Installation Options:
```bash
# Interactive installation (default)
./dataSync-installer.sh

# Non-interactive with custom paths
./dataSync-installer.sh --wsl-dir ~/dev --onedrive-dir '/mnt/c/Users/User/OneDrive/projects/wsl'

# Automated deployment
./dataSync-installer.sh --non-interactive --wsl-dir ~/code --onedrive-dir '/path/to/onedrive'
```

#### Generated Configuration:
**Location**: `~/.config/SyncKit/config`

```bash
# WSL-OneDrive Sync Configuration
# Generated by SyncKit installer on 2025-10-06

# WSL Projects Directory (auto-detected or user-specified)
WSL_PROJECTS_DIR="/home/user/dev"  # Based on detection logic

# OneDrive WSL Directory (auto-detected or user-specified) 
ONEDRIVE_WSL_DIR="/mnt/c/Users/User/OneDrive - Company/projects/wsl"

# Tracking Files
LAST_SYNC_FILE="$DATA_DIR/.last_sync_time"
LOG_FILE="$LOG_DIR/sync.log"
```

### 3. Scheduling System

**Implementation**: Cron-based scheduling  
**Frequency**: Every 5 minutes  
**Configuration**: 
```cron
*/5 * * * * HOME=/home/brett USER=brett PATH=/usr/local/bin:/usr/bin:/bin /home/brett/.local/bin/wsl-smart-sync
```

**Environment Variables Set**:
- `HOME=/home/brett` - Ensures proper home directory access
- `USER=brett` - Sets user context
- `PATH=/usr/local/bin:/usr/bin:/bin` - Minimal but sufficient PATH

### 4. Enhanced Logging & Diagnostics

#### Log Levels:
- **[DEBUG]**: Environment checks, file detection, configuration validation
- **[INFO]**: Sync start/completion, file counts, transfer statistics  
- **[WARN]**: Non-critical issues (temp files, open files)
- **[ERROR]**: Sync failures, permission issues, path problems

#### Diagnostic Features:
- **Environment Validation**: Directory accessibility, permissions, disk space
- **OneDrive Conflict Detection**: Identifies active OneDrive sync operations
- **Open File Detection**: Uses `lsof` to identify files in use
- **Detailed Error Capture**: Separate stdout/stderr from rsync
- **Performance Metrics**: Transfer rates, file counts, data volumes

### 5. Git Repository Detection & Smart Exclusions

#### Git Detection Logic:
```bash
# Detects git repositories using two methods:
1. Directory contains .git folder
2. git rev-parse --git-dir succeeds (for worktrees, submodules)
```

#### Why Git Exclusion is Critical:
- **Branch Conflicts**: Different workstations may have different branches checked out
- **Merge Issues**: Sync could overwrite uncommitted changes
- **Repository Integrity**: Git metadata could be corrupted by file sync
- **Performance**: Git repositories are typically large and change frequently

#### Smart Exclusion Strategy:
```bash
# Pattern-based exclusions (all scripts)
EXCLUDE_PATTERNS=(
    "*.tmp" "*.log" ".DS_Store" "Thumbs.db" "~$*"
    "*.swp" "*.swo" "*.bak" "*.lock"
    "node_modules" "build" "dist" ".dart_tool"
)

# Git repository exclusions (entire directories)
# Dynamically detected and excluded per sync operation
```

### 6. Optimized Data Flow

```
1. Cron Trigger (Every 5 minutes) OR Manual Execution
   ↓
2. Configuration Loading
   ├── Load user-configured WSL and OneDrive paths
   ├── Initialize bidirectional conflict detection
   └── Set up performance tracking
   ↓
3. Environment Validation
   ├── Validate configured directories exist and are accessible
   ├── Check disk space and permissions
   └── Verify OneDrive mount status
   ↓
4. Git Repository Scanning
   ├── Scan WSL directory for git repositories
   ├── Scan OneDrive directory for git repositories  
   ├── Build dynamic exclusion lists
   └── Log excluded repositories
   ↓
5. Fast Change Detection (Optimized)
   ├── Build file state databases (size:mtime:path)
   ├── Compare current state vs. cached state
   ├── Batch process file checks (1000 file batches)
   └── Generate change lists for both directions
   ↓
6. Conflict Detection (if both sides changed)
   ├── Cross-reference change lists
   ├── Apply conflict window (default: 30 minutes)
   ├── Log conflicts requiring manual resolution
   └── Exit if unresolvable conflicts found
   ↓
7. Smart Sync Execution
   ├── Use rsync with --files-from for targeted sync
   ├── Apply git exclusions and pattern exclusions
   ├── Execute bidirectional sync (WSL ↔ OneDrive)
   └── Update sync markers on success
   ↓
8. Performance & Result Logging
   ├── Log timing metrics and file counts
   ├── Update state databases
   └── Record sync statistics
```

### 7. Error Handling & Recovery

#### Common Failure Scenarios:
1. **Permission Issues**: Read-only files, insufficient write access
2. **OneDrive Conflicts**: Active sync operations creating temporary files
3. **Network/Mount Issues**: SMB mount problems, network interruption
4. **Disk Space**: Insufficient space on destination
5. **File Locks**: Applications holding files open during sync

#### Recovery Mechanisms:
- **Automatic Retry**: Cron reschedules every 5 minutes
- **Partial Sync Recovery**: rsync resumes interrupted transfers
- **Conflict Detection**: Identifies and logs sync conflicts
- **Manual Override**: Can be run manually for immediate sync

## Technical Specifications

### Dependencies:
- **rsync**: File synchronization utility (with --files-from support)
- **find**: File discovery and timestamp comparison
- **git**: Repository detection (git rev-parse)
- **stat**: File metadata extraction (size, mtime)
- **grep**: Pattern matching and text processing
- **cron**: Task scheduling
- **lsof**: Open file detection (optional)
- **df**: Disk space monitoring

### Performance Characteristics:
- **Source Size**: ~7.7GB project directory
- **Sync Frequency**: Every 5 minutes
- **Change Detection**: Timestamp-based (efficient for large directories)
- **Transfer Method**: Delta sync via rsync (only changed files)

### Platform Requirements:
- **WSL**: Windows Subsystem for Linux (Ubuntu 24.04)
- **OneDrive**: Business account with sufficient storage
- **File System**: WSL ext4 → NTFS (via SMB mount)
